# Alexa+ add-on package — CareCompanion

Everything Amazon's onboarding asks for, kept next to the server that backs it: the store-listing manifest, the icons
and carousel image at the exact sizes the listing wants, the SVG sources they are rendered from, the privacy policy and
terms of use, and the script that regenerates the media and verifies it.

```
addon-package/
├── addon.json               store listing (en-US) + the MCP integration endpoint
├── README.md                this file
├── legal/
│   ├── privacy-policy.md    linked from addon.json (privacyPolicyUrl)
│   └── terms-of-use.md      linked from addon.json (termsOfUseUrl)
├── media/                   generated PNGs — do not edit by hand
│   ├── icon-light-{64x64,72x72,88x88,126x126,180x180,241x241}.png
│   ├── icon-dark-{same six sizes}.png
│   └── carousel-1-600x900.png
└── source/
    ├── icon.svg             light icon
    └── icon-dark.svg        dark icon
scripts/addon-assets.mjs     renders media/ from source/ and docs/figures/web-app-guard.png, then verifies every size
```

## What the listing says

- **Name** CareCompanion, with a spoken form in IPA (`kɛr kəmˈpænjən`, written the way SSML's `ph` attribute takes it,
  without surrounding slashes) so Alexa+ pronounces it "care companion".
- **Short description** (157 characters) and a **full description** that lead with what the add-on does and state
  plainly that it is a coordination and reminder tool, not medical advice, running a fictional household (Eleanor
  Whitfield, 78, and her caregivers Priya and Daniel) with synthetic data, no accounts and no personal data.
- **Example phrases** are things a customer says: "Alexa, what's my plan today", "Alexa, I took my blood pressure
  pill", "Alexa, I'm feeling a bit dizzy", "Alexa, how is Mom doing this week".
- **Distribution** United States, where the Alexa+ MCP Toolkit operates.
- **Integration** one MCP endpoint of type HTTPS: the server's Streamable HTTP `/mcp` route (MCP spec 2025-11-25,
  sessionful; see the repository README for the transport, the tools and the MCP App).

`addon.json` follows the manifest shape seen in the toolkit's public sample (`manifestVersion`, `storeListing` with
per-locale name, descriptions, example phrases, privacy/terms URLs and media assets, and an `integrations` entry of
type `MCP`). The manifest `alexa-ai` generates is authoritative for field names: diff the two before deploying.

## How it maps to the Alexa+ QuickStart

The QuickStart scaffolds an add-on project from a running MCP endpoint:

```bash
alexa-ai configure                                   # Login with Amazon
alexa-ai new mcp --name "CareCompanion" --locale en-US --mcp-server-url "https://<render-host>/mcp"
alexa-ai deploy                                      # development stage → Add-on ID → web simulator
```

`alexa-ai new mcp` writes the project's manifest with the name, locale and endpoint; `addon.json` is the completed
version of that manifest, so its values can be pasted into (or replace) the generated file before `alexa-ai deploy`.
After deployment, Amazon's Local Inspector (`addon-local-inspector https://<render-host>/mcp`) renders the
`caregiver_summary` MCP App in the Small and Large device frames the dashboard was built for.

| `addon.json`                                                         | Comes from                                                          |
| -------------------------------------------------------------------- | ------------------------------------------------------------------- |
| `storeListing.locales.en-US` name, descriptions, example phrases     | this package                                                        |
| `privacyAndCompliance.privacyPolicyUrl` / `termsOfUseUrl`            | `legal/*.md` on GitHub (blob URLs)                                  |
| `mediaAssets.icons.light` / `.dark` (6 sizes each), `carouselImages` | `media/*.png` on GitHub (raw URLs), regenerated by the script below |
| `integrations[0].config.endpoints.default.uri`                       | the deployed server's `/mcp`                                        |

## Placeholders to fill after deployment

1. **`integrations[0].config.endpoints.default.uri`** — `https://<render-host>/mcp`. Replace `<render-host>` with the
   hostname Render assigns (the service in `render.yaml` is named `carecompanion`, so `carecompanion.onrender.com` or
   a suffixed variant if that name is taken). The same placeholder appears in the commands above.
2. **Media and legal URLs** point at `main` of `github.com/skiitk2510/carecompanion`; they resolve as soon as this
   directory is pushed. Nothing to edit unless the repository or branch moves.
3. **Authentication** — the public demo runs `/mcp` open on purpose (synthetic household, no PHI). If the deployment
   switches on the Tier-1 service-level auth built into the server (`MCP_AUTH=client_credentials` plus
   `MCP_CLIENT_ID`, `MCP_CLIENT_SECRET`, `PUBLIC_URL`), give the toolkit's authentication step the token endpoint
   `https://<render-host>/oauth/token` (OAuth 2.0 client-credentials grant, HTTP Basic client auth) and the client id
   and secret; discovery documents are served at `/.well-known/oauth-authorization-server` and
   `/.well-known/oauth-protected-resource/mcp`. `addon.json` itself does not change.

## Status: why this is not deployed

Per the organizers' statement during the hackathon, the Alexa+ MCP Toolkit (`alexa-ai`, the web simulator and the
Local Inspector) was not available to participants, so this package could not be registered, deployed or certified. It
exists to show readiness: the endpoint meets the toolkit's documented requirements (Streamable HTTP, MCP 2025-11-25, a
remote HTTPS URL, tools well inside the 500 ms budget, visuals via MCP Apps, Tier-1 auth available), and the listing,
media and legal documents are complete, so onboarding is a matter of filling in the endpoint and running the three
commands above.

## Regenerating the media

```bash
npm run addon:assets        # = node scripts/addon-assets.mjs
```

Needs a local Chrome (defaults to the macOS install; override with `CHROME=/path/to/chrome`) and the `puppeteer-core`
dev dependency. The script renders `source/icon.svg` and `source/icon-dark.svg` at 64, 72, 88, 126, 180 and 241 px
with transparent corners, composites the 600x900 carousel card from `docs/figures/web-app-guard.png` (title band, the
whole figure scaled to fit, a legible crop of the device panel, a caption and feature chips), then reads each PNG's
IHDR back, asserts the exact dimensions and checks that every `uri` in `addon.json` matches a rendered file of the
declared size. When the figure changes (`npm run figures`), run this again so the carousel matches.

Icon: a tilted two-tone pill capsule with a shield-check badge tucked into its lower right, on a rounded soft
teal-to-blue tile (light) or a deep navy tile with a light edge (dark). No text, so it survives the 64 px size.

## Checks

```bash
node -e "JSON.parse(require('fs').readFileSync('addon-package/addon.json','utf8'))"

npx prettier --check addon-package scripts/addon-assets.mjs

```
